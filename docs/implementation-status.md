# 完善路线与验收范围

## 第一优先级：现有功能执行链

- worktree 绑定 Agent 和本地工具工作目录，进入/退出恢复目录，不改变进程 cwd。
- Skill fork 获取当前对话，独立工具注册表，继承权限与预算；无人值守审批请求被拒绝。
- 记忆整理通过真实 Agent 执行，写入限制在两个记忆根目录的 Markdown 文件，支持受限删除与锁回滚。
- Agent Hook 执行只读、有限轮次的检查，命令 Hook 采用当前 Agent 目录。
- `/review` 接入命令注册。

## 第二优先级：统一运行与恢复

- TUI、浏览器、单次 CLI 共用 runtime 初始化、工具 wiring、目录恢复和资源关闭。
- 配置 execution 轮次、token 与超时限制，失败原因可见。
- Bash/命令 Hook 超时和取消终止进程树；Bash 连续取消仍等待资源清理。
- 后台任务保存对话、工具结果、工具限制与权限；恢复前保存新检查点，磁盘写入失败时保留原记录。
- 重启不会自动恢复任务；只有 `/tasks resume` 显式继续。
- 普通后台任务完成通知接通，CLI 最终结果在后台处理后输出一次。
- GitHub Actions 已配置 Ubuntu/Windows × Python 3.11/3.13，测试并构建。尚未推送或在 GitHub 执行。

## 第三优先级：可用性与命令隔离

- `--init` 配置向导：独占创建、不覆盖、密钥用环境变量引用。
- `--doctor`：工具、配置、代理端口和沙箱依赖诊断，输出不含密钥。
- `/project`：有条目上限的项目识别。
- `/test` 与 `/test --fix`：正常审批、工作流超时、修复 token 上限和真实重跑；各入口避免重叠操作。
- `/diff` 与 `/rewind`：跟踪文件编辑的差异，准确恢复检查点状态，并覆盖之后首次修改或新建的文件。
- Windows Docker 命令后端：已有 Linux 服务和本地镜像才可用，不安装或启动系统服务，不自动拉取镜像；项目映射 `/workspace`，默认断网，容器只读根目录和受限资源。
- 沙箱执行过程中失效会拒绝运行；缺失的受保护路径通过父目录只读挂载防止新建绕过。

## 真实流程验收

`tests/test_coding_workflow_integration.py` 使用临时 Git 仓库和脚本模型：模型响应是可重复的本地脚本，Git、文件工具和测试子进程是真实执行。

1. 初始化小仓库并提交起始代码。
2. EnterWorktree 真正创建隔离工作区。
3. 真实测试失败，Agent 读取并修复代码，随后真实重跑通过。
4. 检查 diff；分别验证保留和回退，包括删除新建文件。
5. ExitWorktree 恢复 Agent 原目录，保留工作区，宿主 cwd 不变。
6. 中断任务保存工具结果，重启恢复 worktree 和任务，不自动运行、不重复已有写入。
